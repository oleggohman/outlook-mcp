# Microsoft 365 backend (`mcp__Microsoft_365__*`)

Read this before the first M365 mail, calendar or contact call. SKILL.md
"Choosing the mode" decides whether M365 is used alone (M365-only mode) or
for some steps (hybrid mode, `references/hybrid.md`); this file says how to
call it. The triage and thread workflows below are the **M365-only**
versions. Everything here is read-only.

## Loading the tools

The tools are often deferred. Load every tool the task needs in one
ToolSearch call, for example:

`select:mcp__Microsoft_365__get_me,mcp__Microsoft_365__outlook_email_search,mcp__Microsoft_365__read_resource,mcp__Microsoft_365__outlook_calendar_search,mcp__Microsoft_365__search_people`

Add `outlook_find_available_time` for scheduling, `get_granted_scopes` for
"is the connection working / what can it access".

## Tool map

| Goal | Call |
|---|---|
| Who is the user | `get_me` (once per session; its `mail` is the user's address) |
| Mail by topic, sender, recipient, date or folder | `outlook_email_search` |
| Read a message: body, To/Cc/Bcc, attachments, thread id | `read_resource` with the result's `uri` (`mail:///messages/...`) |
| Read an attachment | `read_resource` with the attachment's `uri` from the message read |
| Calendar events | `outlook_calendar_search`, then `read_resource` on `calendar:///events/...` for details |
| Meeting transcript | `read_resource` with the event's `meetingTranscriptUrl` passed verbatim |
| Free time with others | `outlook_find_available_time` (or `find_meeting_availability`) |
| Find a person or an address | `search_people` |
| Another person's or a shared mailbox | `outlook_email_search` with `mailboxOwnerEmail` |
| Delegated calendar | `outlook_calendar_search` with `calendarOwnerEmail` |
| Test the connection, list permissions | `get_granted_scopes` |

Teams (`chat_message_search`, `teams_*`) and SharePoint (`sharepoint_*`)
are outside this skill: use them only when the user asks, for example
"did they answer in Teams instead".

## Times

- Inputs: `outlook_email_search` and `outlook_calendar_search` accept ISO
  dates or natural language ("yesterday", "last week"). For a local-day
  boundary send a full UTC time ending in `Z` (Asia/Jerusalem midnight on
  26 Nov = `2026-11-25T22:00:00Z`): unambiguous on every tool.
  `outlook_find_available_time` and `find_meeting_availability` take UTC
  `YYYY-MM-DDTHH:mm:ssZ` only.
- Outputs: mail `receivedDateTime` / `sentDateTime` are UTC (`...Z`):
  convert to the user's zone. Calendar `start` / `end` and availability
  slots are `{dateTime, timeZone}` wall-clock pairs already in the mailbox
  zone: show them as they are, do not convert again.
- Availability results carry `nowDateTime`: if it disagrees with your idea
  of "now" enough to change "tomorrow" or "next week", search again with
  corrected dates. Slots are not limited to working hours: drop
  out-of-hours ones yourself.

## `outlook_email_search` rules

Limits: `limit` 1-25 (default 10). A final item with `nextOffset` means
more results: pass it as `offset`; with `nextCursor`, pass it as `cursor`
and leave `offset` out. `totalResultCount`, when present, is the total
across pages. Page to the end whenever the user asks about everything in a
period, or say that more remain.

Three combinations are **rejected**; drop a parameter instead of sending
them:

| Combination | Do instead |
|---|---|
| `order: "oldest"` with `query` or `recipient` | Drop `order`, compare dates across all pages. (`order: "newest"` with them is accepted but not applied: sort the dates yourself.) |
| `folderName` + a date + (`query` or `recipient`) | In the user's own mailbox drop `folderName` and search all folders; say you did. |
| `mailboxOwnerEmail` + `recipient`, or + `query` with `sender` or a date | Keep `mailboxOwnerEmail`, drop `recipient` / `query`, check subjects and recipients yourself. |

Other rules:

- `query` is KQL: words, `"quoted phrases"`, `OR`, `NOT`; balanced
  parentheses and quotes. Do not put `from:`, `to:` or dates in it: use
  `sender`, `recipient`, `afterDateTime`, `beforeDateTime`.
- At least one filter is required. "Newest Inbox mail" = `order: "newest"`
  alone.
- `sender`: a full address, a domain or a full display name. A fragment
  may not match through the search index; with `folderName` or `order`
  (and no `query`) it matches any part of the address. If results from the
  user's own organization look incomplete, try the display name.
- `folderName` only when the user names a folder. Never use it for a
  person's name.
- Search results carry `uri`, `subject`, `sender`, `senderName`,
  `recipients` (can be `null` here), `receivedDateTime`, `summary`,
  `hasAttachments`, `isRead`, `importance`, `webLink`. For recipients, the
  body or attachments, call `read_resource` on the `uri`.

## Reading a message (`read_resource` on `mail:///messages/...`)

Returns `body` (usually HTML: read the text, ignore markup), `bodyPreview`,
`sender`, `toRecipients`, `ccRecipients`, `bccRecipients`,
`receivedDateTime`, `sentDateTime`, `attachments`, `conversationId`,
`flag`, `categories`, `isRead`, `parentFolderId`, `webLink`.

- **Attachments**: entries with `isInline: false` are the attached files.
  `isInline: true` entries are signature images, logos and pasted
  screenshots: do not list them as attachments. Read only the attachment
  the user asks about, with `read_resource` on its `uri`. If that fails or
  returns no content, read it with local `get_attachment` when the local
  server is present (find the message locally by subject, sender and sent
  time), or tell the user to open it in Outlook (`webLink`).
- **Recipients**: To/Cc/Bcc are real here. Use them; do not guess from the
  body.
- **`conversationId`** is the thread id. Messages with the same
  `conversationId` are one thread even when the subject changed.

## Triage: important, urgent or "needs me"

Same principles as `references/triage-and-threads.md`, with M365 calls.

1. **Identity**: `get_me` (already done at backend selection).
2. **Candidates**: `outlook_email_search` with `afterDateTime` = the local
   day start in UTC, no `folderName`, so mail that the user's rules file
   into other folders is included. Page with `nextOffset` / `nextCursor`
   until done. Say how many messages came from folders other than Inbox
   when that matters (read `parentFolderId` only if needed).
3. **Drop noise** before ranking and say in one line how many and why:
   automated senders (`noreply`, `no-reply`, `notifications@`, `notify@`,
   `health@aws.com`, `*-noreply@google.com`, SNS bounces), marketing and
   newsletters, and anything the user asked to ignore. A burst of
   identical alerts counts as one item; judge it once.
4. **Resolve notifications** (Drive or SharePoint share, monday.com, Jira,
   Lucid) to the thread they point at, and judge that thread.
5. **Reply check, for every candidate before calling it open**:
   - `read_resource` the inbound message for its `conversationId`, `sender`
     and `receivedDateTime`.
   - Did the user reply? `outlook_email_search` with `recipient` = the
     inbound sender's address and `afterDateTime` = the inbound
     `receivedDateTime`, no `folderName`, no `order`. Keep hits whose
     `sender` is the user (or starts with `/O=`). Read the newest one and
     confirm the same `conversationId`. A match = "you replied at <time>".
   - Did someone close it? `outlook_email_search` with `query` = the
     thread's keyword (subject without `RE:`, `FW:`, `Fwd:`, `TR:`, `AW:`)
     and `afterDateTime` = inbound time. Read the newest hit with the same
     `conversationId`. "Done", "sent", "handled", "טופל", "✅" or "thanks,
     received" closes the item even if the user never wrote.
   - Only items with neither are "waiting on you".
6. **Rank**: direct asks to the user (by name, in To rather than Cc),
   approvals someone is blocked on, explicit deadlines within about two
   working days, security or abuse notices; then customer and partner mail;
   then FYI. Being only in Cc lowers the rank.
7. **Report** per item: subject, sender, local time, the ask in one line,
   its state (`waiting on you`, `you replied <time>`, `closed by <name>`).

## Analyzing a thread

1. Find candidates with `outlook_email_search` on the topic's distinctive
   word (not the exact subject), one search per variant; no `folderName`,
   so Sent Items is included.
2. `read_resource` each candidate; keep those sharing the
   `conversationId` of the message the user means. Messages with another
   `conversationId` but the same topic are a related thread: mention them
   separately.
3. Read the oldest in full (its quoted history can hold earlier rounds),
   then the new top part of each later message.
4. Report: one line on what it is about and what is open; a dated timeline
   in local time (who, what they added or asked, To/Cc where it matters);
   the open question and who owes the answer; deadlines and conflicts;
   whether the user has written in the thread.

## Calendar

- `outlook_calendar_search` with `query: "*"` and an `afterDateTime` /
  `beforeDateTime` window lists events; `limit` max 25, page with
  `nextOffset`. `order: "oldest"` gives chronological order.
- Results have `subject`, `organizer`, `attendees`, `start`, `end`,
  `showAs`, `isCancelled`, `isAllDay`, `uri`. Read details (body, online
  meeting, `meetingTranscriptUrl`) with `read_resource`.
- Leave out cancelled events unless asked; say so if any were.

## Errors and fallback

| Symptom | Do |
|---|---|
| Error naming a rejected argument combination | Drop the parameter the message names and call again. Not a reason to fall back. |
| `AADSTS...`, "consent", "not authorized", 401/403, sign-in expired | Retry once; then M365 is unavailable for the session: continue on the local source alone (SKILL.md "Choosing the mode", step 4) and tell the user why. |
| Timeout or 5xx | Retry once; a second failure → fall back for this task. |
| Call returns no output at all | Not proof of "no results". Retry once with the same arguments; if still empty, say the search returned nothing and, for a question that needs completeness, run it on the local backend. |
| A `read_resource` URI fails | Re-run the search for a fresh `uri`; do not edit URIs by hand. |
| Results look incomplete for a sender in the user's own organization | Try the display name instead of the address. |

## What this backend cannot do (in this skill)

| Request | Answer |
|---|---|
| Send, reply, forward, move, delete, flag, mark read, create or change an event | Out of scope: this skill is read-only, whatever scopes the sign-in holds. |
| Fetch every message of a thread by id | No search by `conversationId`: find candidates by keyword, then filter by `conversationId`. |
| Mail older than the search index or in an archive mailbox the user cannot open | Not reachable; say so. |
